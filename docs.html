Beginner's guide

Make every token earn its place.

AI assistants do not only read the words you type. They also receive instructions, chat history, files, tool descriptions, and sometimes extra reasoning work. This page explains the moving parts in plain language and helps you spot where cost, noise, and drift can enter the workflow.

The prompt you type is often the smallest part. The biggest savings usually come from scoping context, keeping reusable instructions stable, and controlling output size.

Token economy

Three token lanes, three cost behaviors

Every AI turn is usually made of input, cached input, and output. Each lane has a different optimization lever.

IN
Billed every turn

Input tokens

These are the words, code, files, instructions, tool descriptions, and chat history sent to the model before it answers.

Beginner action: attach the smallest useful file, function, or selection instead of the whole repo.

CA
Discounted when stable

Cached tokens

Repeated instructions or prefixes may be cheaper when they stay byte-identical across turns.

Beginner action: keep shared instructions short, stable, and reusable instead of pasting a new version every time.

OUT
Often highest cost

Output tokens

These are the visible answer and the extra work the model may do to reason through the response.

Beginner action: ask for the format you need, such as a short answer, table, patch, or 3 bullet summary.

Model routing

Using a frontier model for routine edits can cost more than the task deserves.

Fix: use Auto Mode or a lighter model for simple work.

Maximum reasoning on a typo or formatting issue can multiply spend.

Fix: reserve high reasoning for genuinely hard ambiguity.

Caching

Instruction cache discount

A stable prefix can be reused more cheaply, but constant edits break the benefit.

Fix: keep shared instructions byte-stable when possible.

Sessions

Session lifecycle

By late turns, history can become a large share of what the model reads.

Fix: start fresh, compact, or summarize when switching tasks.

Tools

MCP schema tax

Every enabled tool may add schema text to repeated agent steps.

Fix: audit tools and keep only the useful set enabled.

Tools

Subagent boundary

A helper can read lots of material while the parent chat receives only a summary.

Fix: use subagents for broad exploration and keep main context focused.

Governance

AGENTS.md noise

An auto-generated agent file can become an encyclopedia instead of a guide.

Fix: keep non-obvious risks, constraints, and workflow rules only.

Model

Ask, Plan, Agent

Agent mode can take many steps, so vague prompts can become expensive quickly.

Fix: use Ask for quick answers, Plan for design, Agent for scoped implementation.

Governance

Three-layer budget

Personal habits help, but team policies stop organization-wide runaway spend.

Fix: define defaults, alerts, caps, and exception paths.

Prompt

Language tax

Some languages can take more tokens than English for the same technical request.

Fix: use English for technical prompts when it is appropriate for the team.

        Bloat Score · Under the hood

        An in-depth guide to how the Bloat Score works.

        The Bloat Score is a 0–100 educational signal that estimates how much unnecessary context is riding along with your prompt. This page explains every component, how the points add up, what the bands mean, and walks through real examples so you can predict and lower your score before you click send.

        Try the calculator Jump to examples
        Definition

        What is the Bloat Score?

        Bloat is the input tokens you did not need. Every turn, an AI assistant sees your typed message plus attached files, repeated chat history, enabled tool schemas, always-on instructions, and how broadly you scoped the request. When any of those grows beyond what the task actually requires, the prompt becomes bloated — it costs more, runs slower, and tempts the model to follow side clues.

        It is a signal, not a bill

        The Bloat Score is an educational estimate. It is not a direct measure of token spend or vendor pricing. It tells you whether you are likely overspending tokens.

        It is a 0–100 number

        Six components each contribute weighted points. The sum is clamped to 100. Bands map the score to a plain-English risk level: Low, Medium, High, Critical.

        It changes per turn

        Bloat is dynamic. Removing a file, ending a chat, disabling a tool, or narrowing scope can drop the score noticeably between requests.

        The formula

        Six components, each weighted by impact

        The score adds points across six categories. Heavier weights belong to inputs that grow the fastest in real workflows — files and chat history — while tool schemas have a smaller per-unit weight because each tool is small but they multiply.

        ComponentWhy it bloatsPer-unit weightMax contribution
        Files & references Each attached file is re-sent on every turn until removed. files × 1.6 32 (at 20 files)
        Chat history Older turns get replayed verbatim until you reset or compact. turns × 1.15 46 (at 40 turns)
        Enabled tools Every enabled tool ships its JSON schema in the prompt. tools × 0.42 33.6 (at 80 tools)
        Always-on instructions Project + user + org rules ride every turn. 0 / 8 / 18 / 28 (size band) 28 (Huge size)
        Scope precision Broader scope drags in more bytes than the task needs. 0 / 8 / 18 / 28 (precision band) 28 (Whole codebase)
        Filler text Long intros, apologies, repeated background. +8 if present 8

        Total points are summed and then clamped to the range [0, 100]. The clamp means a single component cannot push the score past 100, but two or three together easily can.

        Score bands

        What the number actually means

        The same score moves between four bands. Each band is a different conversation: how to act, how urgent the fix is, and what the likely failure mode looks like.

        0–29
        Low

        Lean prompt. Keep scope tight, keep reusable instructions short, and you are getting good value per token.

        30–59
        Medium

        Some extra context riding along. Trim before it becomes habitual or expensive across many turns.

        60–79
        High

        The model is reading more than it needs. Drift risk goes up, costs grow per turn, and the answer may follow side clues.

        80–100
        Critical

        Heavily bloated. Reset the session, attach exact files, disable unused tools, and shorten always-on instructions.

        Anti-patterns

        Six common bloat traps and how to fix them

        These are the patterns that quietly add 10–30 points without changing what the user actually wanted.

        Bloat trap

        The chat that never ends

        A session has been running for hours. New questions inherit 30+ turns of history that are no longer relevant.

        Lean fix

        Reset or compact

        Start a fresh chat for the new task, or use session compaction to summarize the prior thread into a short brief.

        Bloat trap

        The whole-folder fishing trip

        “Have a look around the auth folder and figure out what to rename.” Folder scope sends every file in the folder.

        Lean fix

        Name the file or selection

        “In auth/session.ts, rename getSession to loadSession and update call sites in this file.”

        Bloat trap

        Every tool turned on, just in case

        50+ MCP tools are enabled. Every tool ships its JSON schema with every turn.

        Lean fix

        Trim to what this project needs

        Disable tools you do not actually use. Most teams only need a small subset (terminal, file edit, search) per workflow.

        Bloat trap

        The ever-growing AGENTS.md

        500+ lines of always-on instructions covering edge cases that come up once a quarter.

        Lean fix

        Move occasional rules into skills

        Keep AGENTS.md to landmines and non-obvious rules. Put workflow-specific guidance in a skill loaded only when needed.

        Bloat trap

        Polite prologue

        “Hi! I hope you’re doing well. Sorry to bother you, but I was wondering if you could possibly help me with…”

        Lean fix

        Lead with the verb

        “Rename getSession to loadSession in auth/session.ts.” Politeness has zero effect on output quality.

        Bloat trap

        Drag-and-drop the whole folder

        15 files attached, of which only 2 are relevant to the change. The rest are noise the model has to ignore.

        Lean fix

        Pin the exact files

        Attach only the files the change touches. If the model needs more, it can ask or use search.

        How to lower it

        A short checklist before you click send

        Run through these in order. The earlier items typically remove the most points for the least effort.

        • Scope down first. Folder → file → selection. Each step removes 10 points and usually improves the answer.
        • Reset the chat when the task changes. If your last 6 turns were about a different feature, start fresh.
        • Detach files you no longer need. Especially after the model has already read them and given you the change.
        • Disable tools that do not apply to this project. Most workflows need fewer than 10 tools.
        • Trim always-on instructions. Move occasional or domain-specific rules into skills or prompts.
        • Drop the prologue. Open with the verb and the file. State the outcome plainly.
        • State a success criterion. Tests pass, output shape, or a visible behavior. This also drops the Drift Score.
        Bloat vs. cost

        Why a high score does not always mean a high bill

        Bloat and cost are correlated, not identical. The Bloat Score does not know your model’s pricing or your cached-token discount — it measures how much extra context you are sending. Use the cost calculator alongside it to translate that volume into dollars.

        High bloat, modest cost

        A heavy stable instruction prefix can dominate the prompt yet still be inexpensive when it qualifies for the cached-input rate (typically about 10% of the input price).

        Action: keep the prefix byte-identical so it stays cached, and trim the non-cached portions.

        Modest bloat, surprising cost

        A lean prompt sent to a powerful model with high reasoning effort and a long output can still cost more per turn than a bloated prompt to a lightweight model.

        Action: route routine work to lightweight models and use high reasoning only for genuinely hard problems.

        FAQ

        Frequently asked questions

        Is the Bloat Score the same as token count?

        No. Token count is a measured number reported by the model. The Bloat Score is an educational estimate based on factors that drive token count up. Two prompts with the same token count can have very different Bloat Scores if one of them is mostly stable cached prefix.

        Why are weights different across components?

        The weights reflect typical real-world impact. A single attached file can be hundreds of lines (1.6 weight), a chat turn is usually a paragraph or two (1.15 weight), and a tool schema is short but they add up linearly (0.42 weight). Always-on instructions and scope are stepped because their impact comes in discrete jumps.

        Why does the score cap at 100?

        Clamping makes the score human-readable. Past a certain point, more bloat is more bloat — the practical advice (reset, narrow scope, trim) does not change whether the raw total is 110 or 200.

        Does removing files always lower the score?

        Yes — each file detached removes 1.6 points. If you can also narrow scope from folder to file at the same time, you remove a 10-point step on top of that.

        Should I aim for a Bloat Score of 0?

        No. Some context is necessary. Aim for the lowest score that still gives the model what it needs to do the job correctly — usually that is somewhere in the Low band (0–29).

        How is this different from the AI Drift Score?

        Bloat Score measures unnecessary input. Drift Score measures the chance the output wanders away from the real task. They are correlated — bloated context invites drift — but you can have one without the other.

        An in-depth guide to how the AI Drift Score works.

        The AI Drift Score is a 0–100 educational signal that estimates how likely the assistant’s answer is to wander away from the real task. This page explains every component, the math behind it, what the bands mean, and walks through real examples so you can predict and lower drift before you click send.

        Try the calculator Jump to examples
        Definition

        What is the AI Drift Score?

        Drift is the gap between what you wanted and what the model decided to optimize for. Even a capable model can produce a confident, well-written, completely off-target answer when the request is unclear, contradictory, or buried under stale or unrelated context. Drift is independent of model strength — it is a function of the prompt and the surrounding session.

        It measures intent risk, not output quality

        Drift Score does not score whether the answer is correct. It scores whether the conditions exist for the model to silently solve the wrong problem.

        It is a 0–100 number

        Six components contribute weighted points based on how strongly each one pulls the answer off-target. The sum is clamped to 100 and mapped to four bands.

        It is fixable in seconds

        Unlike model errors, drift signals are usually one rewrite away from a much lower score: clarify the outcome, add a success criterion, drop the conflicting rule.

        The formula

        Six components, each weighted by how strongly it pulls focus

        Heavier weights belong to inputs that most reliably cause off-target output: clarity gap (because every other lever depends on it) and explicit conflicts (because the model must pick a side, often the wrong one).

        ComponentWhy it causes driftPer-unit weightMax contribution
        Clarity gap If the outcome is fuzzy, the model invents a plausible one. (10 − clarity) × 4.5 45 (clarity 0/10)
        Stale history Old turns suggest the model is still “doing” the previous task. stale × 4 40 (stale 10/10)
        Multi-goal prompt Each extra goal splits attention across competing outcomes. max(0, goals − 1) × 4 28 (8 goals)
        Unrelated files Irrelevant attachments become tempting false clues. files × 4.2 50.4 (12 files)
        Conflicting rules Contradictions force the model to pick a side, often the wrong one. +18 if present 18
        Missing success criteria Without an acceptance signal, the model cannot self-check. +14 if missing 14

        Total points are summed and clamped to [0, 100]. Note that clarity is the only inverted input — higher clarity reduces points; every other lever adds points as the input grows.

        Score bands

        What the number actually means

        Drift bands are about confidence in the outcome. The same model can land cleanly in one band and wander in another — the band is set by the prompt, not the model.

        0–29
        On-track

        The task is clear enough for the assistant to stay focused. Validate the answer against your criteria and move on.

        30–59
        Watch

        The answer may follow a side goal or stale history. Skim the output before accepting and re-state the outcome if needed.

        60–79
        Drifting

        Drift risk is high. Clarify the desired outcome and remove unrelated context before proceeding.

        80–100
        High drift

        The assistant is likely to wander. Split the work, reset the chat, and state success criteria explicitly.

        Anti-patterns

        Six common drift traps and how to fix them

        These are the prompt shapes that quietly raise the drift score without changing the user’s actual intent.

        Drift trap

        The vague verb

        “Clean things up”, “make it better”, “improve performance” — the model has to invent what “better” means.

        Lean fix

        State the observable change

        “Reduce signIn() error rate to zero for passwords containing a colon. The test in login.test.ts should pass.”

        Drift trap

        Two goals in one breath

        “Fix the bug and refactor the helper while you’re in there.” The model can do either well, but rarely both.

        Lean fix

        Split the prompt

        Do the bug fix first, validate it, then ask for the refactor as a separate request with its own success criteria.

        Drift trap

        Riding on yesterday’s chat

        The previous 10 turns were about a different feature. The model still sees them and assumes they remain relevant.

        Lean fix

        Start a fresh chat or summarize

        Open a new conversation for the new task, or paste a one-paragraph summary of the relevant prior context.

        Drift trap

        The contradictory rules

        One instruction says “be concise”, another says “include exhaustive comments and explanations.” The model picks one and disappoints on the other.

        Lean fix

        Reconcile before asking

        Pick the rule that applies to this task, restate it once, and remove the contradicting one for this turn.

        Drift trap

        The stowaway file

        You attached 8 files, but only 2 are relevant. The other 6 contain code names and patterns that look authoritative.

        Lean fix

        Pin only the files the change touches

        Trim the attachment list. If the model needs more, it can ask or use search — you do not have to pre-load everything.

        Drift trap

        No definition of “done”

        “Refactor this and tell me when it’s good.” The model has no acceptance signal, so it stops when it feels satisfied.

        Lean fix

        State the criterion

        “Tests pass”, “function returns a string of shape X”, or “no eslint errors” — any concrete signal lets the model self-check.

        How to lower it

        A short checklist before you click send

        Run through these in order. The earlier items typically remove the most drift points for the least effort.

        • Write the outcome as one sentence. If you cannot, the prompt is not ready — refine it before sending. This alone can remove 20+ points.
        • Add a success criterion. Tests pass, output shape, file changed, page renders — any concrete signal removes 14 points and lets the model self-check.
        • Keep one goal per prompt. Each extra goal is +4 points and roughly halves the chance the answer addresses both.
        • Reset the chat when the task changes. Stale history is a per-point linear hit and a confidence multiplier on the wrong context.
        • Resolve any contradictions in your rules. A single conflict is +18 points and forces the model to silently pick a side.
        • Detach files that are not part of the change. Each unrelated file is +4.2 points and a tempting false clue.
        • Re-read your prompt from the model’s perspective. If the words could mean two different things, edit until they cannot.
        Drift vs. bloat

        Two different signals about the same prompt

        Bloat measures unnecessary input; Drift measures the chance the output wanders. They are correlated — bloated context invites drift — but you can have one without the other.

        Low bloat, high drift

        A short prompt with a vague verb and no success criterion. The token count is tiny, but the model has nothing to anchor on.

        Action: rewrite the outcome and add a concrete acceptance signal.

        High bloat, low drift

        A long, file-heavy prompt that names the exact change and includes a passing test as the criterion. Expensive, but unlikely to drift.

        Action: trim files and history to bring bloat down without losing the clarity that keeps drift low.

        FAQ

        Frequently asked questions

        Is the AI Drift Score the same as accuracy?

        No. Accuracy is a property of the answer; Drift is a property of the prompt. A high Drift Score predicts a higher chance of an inaccurate answer, but a low Drift Score does not guarantee correctness — the model can still make mistakes inside a clear prompt.

        Why is clarity weighted so heavily?

        Because every other lever depends on it. If the outcome is unclear, even a short, conflict-free, clean-history prompt can still drift. Clarity is the only inverted input — raising it from 5 to 9 removes 18 points instantly.

        Why does a single conflict cost 18 points?

        Conflicts force the model into a discrete choice that you did not make. Unlike stale history (which just adds noise), a conflict actively rewards one outcome and penalizes another — whichever side the model picks, it disappoints the rule on the other side.

        Does a high Drift Score always produce a wrong answer?

        No. A capable model can still land correctly on a high-drift prompt, particularly with luck or repeated retries. The score predicts the probability of drift over many requests — not the outcome of any single one.

        Should I aim for a Drift Score of 0?

        You usually cannot. Some clarity gap is unavoidable in real prompts, and even a perfectly worded request gets ~5 points from a healthy clarity rating. Aim for the On-track band (0–29).

        How is this different from the Bloat Score?

        Bloat is about how much extra input rides along; Drift is about how likely the output is to wander. A bloated prompt can still be perfectly on-target if the outcome and acceptance criteria are explicit, and a lean prompt can still drift badly if the verb is vague.
